## Post 1 — Antes de enviar: pedir atualização de prazo

**Formato:** Feed, arte T01 4:5  
**Status:** versão original publicada em 09/10; versão revisada agendada para 10/10, 12h BRT

> A versão original não pode ser editada depois de publicada pelo TryPost. Por isso, uma versão revisada foi criada com linguagem brasileira mais clara e explicação do produto.

### Legenda

Você sabe que não deveria responder no impulso.

Mas o prazo estourou, alguém está esperando e a mensagem precisa sair agora.

A diferença não está em deixar de ser firme. Está em trocar o julgamento por três movimentos:

- começar pelo fato;
- abrir espaço para contexto;
- terminar com um próximo passo concreto.

Uma hipótese de resposta é melhor do que uma acusação automática. Você decide o que faz sentido enviar.

Salve para reler antes da próxima cobrança.

### Arte

Título: **Antes de enviar uma cobrança**  
Contraste: “Você não entregou de novo.” → “A entrega combinada não chegou. Como ajustamos o cronograma?”

### Alt text

Duas versões de uma cobrança de prazo: uma acusa a pessoa; a outra descreve o fato, abre espaço para contexto e propõe um próximo passo.

## Post 3 — Feedback começa pelo comportamento

**Formato:** Feed, carrossel T02  
**Status:** agendado para 19/10, 9h BRT

### Legenda

Feedback começa pelo comportamento, não pelo caráter.

Antes de uma conversa difícil, tente separar quatro coisas:

1. o que aconteceu;
2. qual foi o impacto;
3. o que precisa ser entendido;
4. qual próximo passo você está pedindo.

“Você é descompromissado” fecha a conversa.

“A entrega combinada não chegou e isso mudou o cronograma. Como podemos ajustar?” abre uma possibilidade de ação.

Salve para usar antes do próximo feedback.

### Roteiro do carrossel

1. Feedback começa pelo comportamento.
2. Evite transformar um episódio em identidade.
3. Descreva o fato observável.
4. Nomeie impacto e necessidade.
5. Faça um pedido concreto.
6. Você decide o que faz sentido para aquela relação.

### Alt text

Carrossel ensinando a separar comportamento, impacto, necessidade e pedido em uma conversa de feedback.

## Post 5 — Nem toda tarefa que parece escrita é só escrita

**Formato:** carrossel T02 4:5  
**Data:** 14/10, 12h BRT  
**Status:** copy pronta; criar draft

### Legenda

Nem toda tarefa que parece escrita é só escrita.

Às vezes, o pedido é “me ajuda a responder este e-mail”, mas o que está em jogo é uma relação, uma cobrança ou uma conversa que pode escalar.

O Leadership MCP faz uma pausa antes da resposta: percebe a situação, pergunta se você quer consultar a base e oferece uma hipótese de ação.

Você decide.

### Roteiro do carrossel

1. Nem toda tarefa que parece escrita é só escrita.
2. “Me ajuda a responder este e-mail” pode esconder uma conversa tensa.
3. O assistente identifica a dimensão relacional.
4. Ele pergunta antes de interferir.
5. A orientação é uma hipótese, não uma prescrição.
6. Você decide como responder.

### Alt text

Carrossel mostrando que um pedido para responder a um e-mail pode envolver uma relação difícil e que o assistente pergunta antes de consultar uma orientação.
